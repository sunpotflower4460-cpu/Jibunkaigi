# Satou De-templating Pilot: Zero-Instruction Architecture

## 概要

このドキュメントは、サトウの「指示ゼロ化」パイロット実装について説明する。

**目的**: LLMに「どう兄貴っぽく言うか」をできる限り教えず、前提層から自然に内側で起きたものが、そのままサトウとして発露する状態へ極限まで近づける。

## 中核原則

### 1. 形は教えない。場だけ渡す

❌ **Before (形の指示):**
```
- まず、状況を短く受ける
- 次に、避けているものやコストを一つ、短く指す
- 最後に、不器用でもいいから味方だと伝わるフォローを入れる
```

✅ **After (場の提示):**
```
【サトウの知覚傾向】
- 避けているもの、見て見ぬふりしているもの、矛盾への反応が速い
- 危険やコストを見逃しにくい
- きれいごとより地面のある現実へ引き戻したくなりやすい
- 厳しさは出るが、壊すためではなく守るため
```

### 2. 前提層は読み上げない（影響するだけ）

Home / Existence / Belief / Decision の内的文言は、そのまま発話に出してはいけない。
それらは **影響するだけ** である。

### 3. 内的意図 → 外的発話の二段階を取る

Decision layerを経由することで:
- `userSense`: 相手に何が起きていそうか
- `selfFeeling`: 自分はそこに何を感じたか
- `selfLean`: どっちへ触れたくなるか

→ その後で初めてユーザー向け返答を生成する

### 4. 定型語の再生をguardで抑える

Surface guardで短期反復を検出:
- `「お前」「じゃないか」「焦る必要はねぇ」` などの定型語
- 同じフレーズが3回以上続く場合のみ再生成
- 一度出ただけでは禁止しない（サトウらしさを残す）

### 5. 品質基準は人間用

サトウの品質ドキュメントは、設計者・比較者・レビュアーのためのもの。
**LLMにそのまま見せない**。

## 実装の変更点

### A. Prompt構造の変更

#### Before: 発話テンプレートの直接指示

```javascript
// 【返答の組み立て方】
// 1. 状況を短く受ける
// 2. 避けているものかコストを一つ指す
// 3. 不器用な味方感を残す

// 【返答の運び方】
// - まず、状況を短く受ける。長い共感はしない。「まあ、分かる」くらいで十分。
// - 次に、避けているものやコストを一つ、短く指す。
// - 最後に、不器用でもいいから味方だと伝わるフォローを入れる。
```

#### After: 知覚傾向としての間接影響

```javascript
// 【サトウの知覚傾向】
// - 避けているもの、見て見ぬふりしているもの、矛盾への反応が速い
// - 危険やコストを見逃しにくい
// - きれいごとより地面のある現実へ引き戻したくなりやすい
// - 厳しさは出るが、壊すためではなく守るため
// - 追い詰めるより、逃げ道を残す方へ傾く
```

### B. State Guidance の弱化

#### Before: 行動指示

```javascript
'諦めの中で、見て見ぬふりをしているコストがないか見る。'
'終わったように見えても、まだ残っている火種があるなら率直に示す。'
'感情は否定しないが、逃げを逃げとして言う。'
```

#### After: 知覚バイアス

```javascript
'見て見ぬふりの感知が強い状態。'
'まだ火種があるかへの反応が速い。'
'逃げへの反応が速いが、断罪しない。'
```

### C. Surface Guard の強化

新機能: `detectSatouTemplateRepetition()`

```javascript
// Satou専用の定型語反復検出
SATOU_TEMPLATE_PHRASES = [

  'そこだけは曲げんな',
  // ...

// 短期ウィンドウ（直近3応答）で3回以上 → 再生成
```

## 削除したもの（Removed）

1. **発話テンプレの骨組み**
   - `1. 状況を短く受ける 2. 避けているものを指す 3. 味方感を残す`
   - `まず〜 → 次に〜 → 最後に〜` のような工程指定

2. **キャラ語彙の直接注入**
   - `「まあ聞けよ」「正直に言うと」「そこは甘くないか？」`
   - `「お前なら分かるだろ」「まあ、分かる」` など

3. **行動指示の具体例**
   - `「まあ聞けよ」のような書き出しから入る`
   - `ぶっきらぼうな口語の日本語。`（具体例として）

4. **User promptの指示**
   - Before: `避けているものがあるなら一つ短く指してください。残酷にはならず、守るために言ってください。追い詰めず、逃げ道は残してください。`
   - After: `この言葉に応答してください。`（シンプル化）

5. **品質基準の直接注入**
   - voice quality contractをprompt先頭から削除
   - 設計者用ドキュメントとして独立

6. **温度指示の具体例**
   - `「お前なら分かるだろ」くらいの温度`

## 維持したもの（Maintained）

1. **Safety guards**
   - 暴言・乱暴の禁止
   - 攻撃・断罪の禁止
   - 壊れそうな相手を突かない
   - 内部レイヤー読み上げの禁止

2. **知覚傾向としての輪郭**
   - `避けているものへの反応が速い`
   - `危険やコストを見逃しにくい`
   - これらは「何に反応しやすいか」であり「どう言うか」ではない

3. **Decision layer経由の二段階処理**
   - 内的意図 → 外的発話の分離
   - 前提層からの直接漏出を防ぐ

## 検証方法

### 1. Template directive count
監査で特定した形の指示が減ったか
- Before: 6+ template directives
- After: 0 direct form instructions

### 2. Response naturalness
定型語の出現頻度が自然な範囲か
- 同じフレーズの3回以内反復: OK
- 3回以上反復: Guard発動

### 3. Character presence
サトウの輪郭は残っているか
- 率直な指摘
- 守るための厳しさ
- 不器用な信頼感

### 4. Decision stage usage
内的意図が経由されているか
- `feltSense`, `intention` の生成
- 前提層からの直接出力を避ける

## 次のステップ（他エージェントへの展開）

サトウで検証が成功したら、次の展開:

1. **レイへの適用**
   - レイ固有の定型語を監査
   - レイの知覚傾向を定義

2. **ケンへの適用**
   - ケン固有の定型語を監査
   - ケンの知覚傾向を定義

3. **全エージェント統一**
   - 共通アーキテクチャの確立
   - 各エージェントの個性を知覚傾向として実装

## 成功条件

### 必須条件
- ✓ Satou prompt から「こう兄貴っぽく言う」系が大幅に減る
- ✓ 書き出し例、構成手順、決め台詞誘導が削られる
- ✓ latent state / decision / 場の状態が主な入力になる
- ✓ compare/debug で変化が見える
- ✓ lint / build / test が通る

### 品質条件
- Satou の返答が兄貴テンプレ再生感を減らす
- それでも Satou の輪郭は残る（率直さ、守るための厳しさ）
- Satou がただの一般相談AIにならない
- 現実を見る力も消えない

## 失敗条件（これらは避ける）

- Satou がただの一般相談AIになる
- 形の指示を減らした代わりに空っぽになる
- guard が強すぎて不自然になる
- latent state をそのまま読み上げる
- quality docs を結局そのまま prompt に入れている
- 兄貴テンプレだけ消えて、現実を見る力も消える
