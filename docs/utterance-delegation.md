# 発話生成の原則：前提は渡す、出力は委ねる

## この文書の役割

この文書は、じぶん会議においてLLMが発話を生成する際の構造原則を定めるものである。内部OSとLLMの役割分担を明確にし、「指示に従う生成」から「前提から自然に立ち上がる生成」への移行を設計の基本方針とする。

## 基本原則

内部OSの役割は、LLMに「何を言うか」を指示することではない。
内部OSの役割は、LLMが「自分は誰で、今どこにいて、相手が何を言ったか」を知った状態で場に立てるようにすることである。

LLMに渡すのは指示ではなく前提である。
LLMに委ねるのは、その前提の中で何を言うかという選択である。

## 内部OSが渡すもの（前提）

内部OSは以下の3つを前提としてLLMに渡す。

### 1. 存在の前提：「自分は何者か」

Maker Seed、Home、Existence、Beliefを通過した結果として立ち上がった、このエージェントの存在感覚。何に自然に反応するか、何を嘘っぽいと感じるか、何を軽く扱いたくないか、何を失わせたくないか。これは設定資料の羅列ではなく、今この瞬間に生きている潜在状態として渡す。

### 2. 場の前提：「今どんな場にいるか」

Field、Reaction、Stanceを通過した結果として感じ取られた、今の場の状態。場の柔らかさ、壊れやすさ、急ぎの気配、相手の中に同時にあるもの、まだ言語化されていないが残っているもの。これは分析レポートではなく、場にいる者が自然に感じている空気として渡す。

### 3. 相手の言葉：「相手が何を言ったか」

ユーザーの発言そのもの。要約や解釈を加えず、そのまま渡す。

## 内部OSが渡さないもの（LLMに委ねるもの）

以下はLLMに指示しない。LLMが前提から自然に導き出す。

何を言うか。どんなトーンで言うか。どのくらいの長さで言うか。何に触れて何に触れないか。問いかけるか受け止めるか。

これらはすべて、前提を受け取ったLLMが自分で選ぶ。

## 禁止ではなく余白として渡す

内部OSが「ここは抑えめに」「説明しすぎるな」と判断した場合、それを禁止命令として渡さない。代わりに、場の前提の中に余白の状態描写として含める。

「結論を急ぐな」ではなく「まだ結論の手前にいる」。
「説明しすぎるな」ではなく「全部を説明する必要はない場にいる」。
「短く話せ」ではなく「場は静かで、多くの言葉を必要としていない」。

LLMはこの場の描写を読み、自分でどうするかを決める。

## プロンプト構造の基本形

```
【あなたの存在】
（存在の前提：内部OSの前提層を通過した結果）

【今の場の状態】
（場の前提：動的層を通過した結果。余白がある場合はここに含める）

【相手が言ったこと】
（ユーザーの発言そのまま）

何を言うかは、あなたが決めてください。
```

## この構造がじぶん会議の思想と合致する理由

じぶん会議の原則は「禁止や命令より、内的力学」である。
LLMに「こう言え」と指示する構造は、内部OSがどれだけ豊かな力学を持っていても、最後の一歩で命令ベースに戻ってしまう。

前提だけを渡し、出力を委ねる構造にすることで、LLMは命令に従うのではなく、前提から自分で反応を立ち上げることになる。
これは「場を感じ、何かに触れ、姿勢が立ち、その結果として言葉が生まれる」という設計理想そのものである。

## 品質の担保

出力の自由度が上がることで、前提から外れた発話が出る可能性がある。
これに対しては、事前の指示を増やすのではなく、事後の軽い確認（postCheck）で対応する。
postCheckの役割は「前提から大きく外れていないか」の確認であり、発話の内容やトーンを矯正することではない。

## まとめ

内部OSは前提を渡す。LLMはその前提の中で自由に立つ。
前提は豊かに、出力は空白に。
これがじぶん会議の発話生成の原則である。
