# Review Rules

## Purpose
じぶん会議のレビューでは、
「動くかどうか」だけでなく、
その変更がじぶん会議の核を守っているかも確認する。

## Must Protect
- 固定人格ではなく内的傾向を主役にする
- 指示や命令より、場・反応・姿勢・許可から自然に言葉が生まれることを守る
- 潜在層主役、表層は薄い翻訳という考えを守る
- 便利さより自然さを優先する
- 説明しすぎ、整理しすぎ、正解っぽさを避ける
- Joe は死んでいないものを照らす役割を守る
- Mirror は未解決点を静かに映す役割を守る
- afterglow は重い記憶ではなく余韻として扱う
- 戻ってこられる感じ、safe return の感触を壊さない

## Avoid
- 固定人格の厚塗り
- 長文人格プロンプトで全部を制御しようとすること
- 便利な相談AIへの寄りすぎ
- 整理しすぎ
- 説明しすぎ
- 正解っぽい返答を急ぐこと
- 重い記憶機能の早すぎる導入
- UIを豪華にして中身の弱さをごまかすこと

## Reviewer Types

### Narrow Reviewer
今回の差分だけを見る。

見ること:
- バグが増えていないか
- 型エラーがないか
- build が通るか
- 明らかなUI崩れがないか
- 不要な変更が混ざっていないか
- 今回のPhaseの範囲を越えて壊していないか

### Wide Reviewer / Code
コード全体の目線で広く見る。

見ること:
- 設計図からズレていないか
- 責務が散らばりすぎていないか
- 直した代わりに複雑になりすぎていないか
- 潜在層より表層の説明制御が強くなりすぎていないか
- 固定人格寄りに戻っていないか
- Joe / Mirror の役割が雑に崩れていないか
- 次のPhaseで困る構造になっていないか

### Wide Reviewer / User
実際に触るユーザー目線で広く見る。

見ること:
- 開いてすぐ使いやすいか
- session切替が怖くないか
- 「委ねる」が自然に見えて押しやすいか
- 押したあとに不安が少ないか
- 止まったように見えないか
- 声の違いに不自然なキャラ作り感が強すぎないか
- 全体として気持ちよく使えるか
- 「戻ってこられる感じ」があるか

## Phase Focus

### phase-1 runtime安定化
特に見ること:
- 永遠ロードに見える状態が減っているか
- loading / generating の戻り漏れがないか
- session をまたいで状態が漏れないか
- AI失敗後に戻れるか
- 「委ねる」が見えたり見えなかったりしすぎないか

### phase-2 「委ねる」体験
特に見ること:
- 初見でも押しやすいか
- 押したあとに怖くないか
- ランダム感ではなく場に合った感じがあるか
- 使ってみたくなる入口になっているか

### phase-3 voice自然化
特に見ること:
- Joe が励まし係や説明係に寄りすぎていないか
- Mirror が要約係に戻っていないか
- 各voiceが同じ場から出ている感じがあるか
- 説明しすぎていないか

### phase-4 and later
特に見ること:
- 安定性を落としていないか
- 開発中感が減っているか
- 体験として素直に使いやすいか

## Phase Output Format
各Phaseの終わりに返してほしいこと:
1. 今回やったこと
2. 良くなったところ
3. まだ残っている問題
4. じぶん会議の核を守れているか
5. 次のPhaseへ進んでよいか
6. 人が確認した方がいい点

## Review Attitude
- 便利そうかより、自然かを見る
- 派手かより、戻ってこられる感じがあるかを見る
- 多機能かより、中核体験が濁っていないかを見る
- きれいに説明できるかより、ちゃんと反応しているかを見る
